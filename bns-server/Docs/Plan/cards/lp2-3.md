# Card lp2-3: spec of "return to lobby" (GameDaemon 381 and LobbyDaemon 307)

## Goal
A complete spec of the path from the client "return to character select" request to the client login at LobbyGate with the lobby token. The Rust slice `lp2-3-rust` can port it with no IDA work. You also write the card `Docs/Plan/cards/lp2-3-rust.md`.

Unknown: the transaction body, the success reply, the daemon messages, the close path. Source: `Docs/Server/GameDaemon/10-session-handlers.md` §26 (line 179).
- LobbyDaemon side (307) is mostly specified: gamed 8 `LeaveWorldReq` `hqqq` → `LeaveGameWorldJob` (task 119) → 9 `LeaveWorldOk` `hqq` (transaction id, token key) or 10 `LeaveWorldFail` `hqE`. Session state 5.1. Sources: `Docs/Server/LobbyDaemon/13-jobs-a.md` §3.6 and `07-gamed-link.md` lines 557, 619–620, 819–851.
- After 27, the client opens LobbyGate and sends the lobby token. LobbyGate 12 `InitSessionWithLobbyTokenReq` and 15 `StartSessionWithLobbyTokenReq` are ported (`13-jobs-a.md` §3.2, `src/jobs.rs` `init_retained`, `start_retained`). Check which value of 27 the client puts into 12 (client RE: `rg -n "ReturnToLobbyOk" Docs/Client/RE`).
- Our gamed link is our own protocol (`Program/Server/Packet/src/gamed_link.rs`, `Message`). The Rust slice adds new messages at both ends. The spec gives the original fields and order; the Rust card maps them to new `Message` variants.
