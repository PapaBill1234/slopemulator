# Card ld381-2: LobbyDaemon Rust coverage audit and the last Rust cards

## Goal
You make a full list of what the Rust crate `lobbydaemon` does and does not do, against the LobbyDaemon specs (build 381). From the gaps you write 5 Rust cards (`ld381-r1` to `ld381-r5`). When these 5 cards are done, the LobbyDaemon port is complete.

No IDA work. No Rust card with the name `ld381-2-rust`.

## Work
1. Make the matrix. One row for each: handler (5 tables + NP), job class, timer, `LobbyDB` wrapper, config key. Columns: item, spec file and section, Rust item (function or type), test name, state (`done`, `partial`, `missing`, `out of scope`), note.
2. Use `rust_api.py` and the test names. Read a Rust source file only for a row whose state is not clear; read only the lines you need.
3. Write the matrix to `Docs/Server/LobbyDaemon/25-rust-coverage.md` with counts per state at the top.
4. Put every `partial` and `missing` row into one of 5 groups. Write one card for each group with `Docs/Plan/card-template.md` (max 3,000 tokens each):

| Card | Group |
| --- | --- |
| `ld381-r1` | gamed link: world entry, leave world, logout notify, kick, character sync; the work of `lp2-4-rust` |
| `ld381-r2` | account inventory link (23 handlers) and the jobs that use it |
| `ld381-r3` | manage port, InfoGate, timers and schedulers |
| `ld381-r4` | NP (Sts) requests and notifies, charge, goods, grade, promotions |
| `ld381-r5` | database: live SQL, error maps (`dbrtn` → wire codes), time conversion, all remaining wrappers |

5. Each card has the sections "Source rule" and "Architecture rules" from this card. Each card gives exact spec line ranges, Rust signatures, and an acceptance table. A test that checks client bytes uses the 381 format. Each card contains the line `cargo test -p lobbydaemon` and a "## Files" list. A group with no gap gets a card with 1 test that proves the coverage.
6. Write the handoff `Docs/Plan/handoffs/ld381-2.md`.
