# Card ld381-r1: LobbyDaemon gamed link — delete, restore, character and account sync, play times

## Goal
The gamed link carries all world-side messages of LobbyDaemon 381 that are not NP, account inventory or guild work. Delete and restore go to the GameDaemon. Character and account data from the world goes to the database. The 381 lists of `HelloOk`, `EnterWorldOk` and commands 110/113 carry real data.

## Work
1. Packet crate: add the `Message` variants of "Interfaces" with encode/decode. Extend `message_round_trip`.
2. `LinkGameDaemon::delete_character` sends 23 and waits for 24/25 (transaction map, as `kick`). `restore_character` and `restore` send 26 and wait for 27/28. Timeout = the link transaction limit. Map 25/28 reasons as `16-jobs-d.md` lines 151–219 say.
3. GameDaemon `link.rs`: answer 23 and 26. If the PC is not in the world, reply Ok (24 with result 1, 27). Else Fail with reason 2 ❓ and log.
4. Add the 11 `Store` methods of "Interfaces" to `Store`, `SyncStore`, `MemoryStore` and `MssqlStore`. Each MSSQL call uses bound parameters (D1–D5). A non-zero return stays a typed `ProcedureError`.
5. Handlers on the lobby side (a job task, not the link task, for each call that waits for the database): 11 → session bot score (used by the logout write); 39 → key check (mismatch 5), `update_character_data`, reply 40/41; 42 → key check, then in order `update_time_based_play_info`, `update_account_exp`, content quota, recycle time; the first failure code goes in 44 (`20-handlers.md` line 106); 107 → 108/109; 110 → 111/112; 113 → 114/115. Session lookup is by pcid; no session → 5.
6. `EnterGameWorldJob`: call `update_last_play_start`. `LeaveGameWorldJob` and `LogoutInGameWorldJob`: call `update_last_play_end` (`EndGameWorldPlay`).
7. `EnterOk`: fill the time-based play list, the account exp record, the content quota list and the recycle time list from the session cache (loaded at login with the new load methods). `HelloOk`: fill the time-based play season schedule, the random store schedule (`load_random_store_schedule`) and the mileage days (`game-mileage-effective-duration-in-days`, `Settings`, default 0 ❓).
8. Write the facts that you verify into `25-rust-coverage.md`: change the r1 rows to `done`.
